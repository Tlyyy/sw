# 单部署双 UI 拆分与重构总计划

> 制定日期：2026-07-28
> 当前状态：代码重构与本地验收已完成，尚未提交、推送或部署。
> 核心方案：一套部署、两套独立界面、自动分流、一套共享业务核心。

## 1. 最终目标

项目最终保持一个网址、一个构建产物和一套后端数据，但在前端内部形成两棵独立 UI：

```text
同一个网址与部署
        │
        ├─ ≤ 980px  ──> MobileApp
        │                 └─ 手机页面、手机导航、手机交互
        │
        └─ ≥ 981px  ──> DesktopApp
                          └─ PC 页面、PC 导航、PC 交互

MobileApp / DesktopApp
        └─ 共用领域规则、Store、同步、持久化、校验和数据类型
```

必须满足：

1. 用户不需要手动选择端，应用根据视口自动切换。
2. 任一时刻只挂载当前端的界面，不靠 CSS 同时渲染两套页面再隐藏其中一套。
3. 手机端与 PC 端可以独立调整信息架构、布局和操作流程。
4. 两端继续共用同一份账号、库存、任务、核算和同步数据。
5. 路由地址和业务语义保持一致，不出现手机与 PC 数据口径不同。
6. 最终仍执行一次 `vite build`，部署一个 `dist`。

## 2. 不拆分的部分

以下代码继续作为共享业务核心，禁止复制成手机版和 PC 版：

- `src/domain/`：计算、规则、业务模型。
- `src/stores/`：Pinia 状态和业务动作。
- `src/persistence/`：本地持久化。
- `src/sync/`：云同步、加密和重连。
- `src/data/`：目录数据和 Schema。
- 与端无关的类型、校验、格式化和图片生成逻辑。

只有以下内容按端拆分：

- App Shell 和导航。
- 页面结构与信息层级。
- 表格、列表、卡片、Sheet、Dialog 等呈现方式。
- 手机触控流程与 PC 键鼠流程。
- 平台专用样式、动效和页面级组件。

## 3. 目标目录

```text
src/
├─ app/
│  ├─ device.ts                 # 唯一设备模式来源
│  ├─ router.ts                 # 共用 URL 与路由语义
│  └─ platformPages.ts          # 路由到双端页面的映射
│
├─ platforms/
│  ├─ mobile/
│  │  ├─ MobileAppShell.vue
│  │  ├─ pages/
│  │  └─ components/
│  ├─ desktop/
│  │  ├─ DesktopAppShell.vue
│  │  ├─ pages/
│  │  └─ components/
│  └─ shared/
│     ├─ useShellContext.ts
│     └─ PlatformPage.vue
│
├─ features/
│  └─ <business-domain>/
│     ├─ composables/            # 双端共用页面状态与业务动作
│     ├─ models/                 # 页面模型和映射
│     └─ shared-components/      # 真正与端无关的局部组件
│
├─ domain/
├─ stores/
├─ persistence/
└─ sync/
```

目录只表达所有权，不要求一次性移动全部文件。页面迁移到哪一步，目录就整理到哪一步。

## 5. 拆分原则

### 5.1 采用纵向切片

每次完整迁移一个业务页面：

1. 锁定当前业务行为和数据口径。
2. 抽出共用 composable、页面模型与动作。
3. 实现手机页面。
4. 实现 PC 页面。
5. 接入自动分流。
6. 完成双端测试和视觉验收。
7. 删除原组件内已经失效的响应式分支。

不采用“先复制全站为两份，再分别修复”的方式，避免业务逻辑永久分叉。

### 5.2 禁止的实现

- 在一个大型 `.vue` 文件中堆叠整页级 `v-if="isMobile"`。
- 同时挂载手机和 PC DOM，再通过 `display: none` 隐藏一端。
- 在多个页面重复不同的设备判断规则。
- 根据 User-Agent 决定 UI。
- 在手机页面和 PC 页面各复制一份保存、计算或同步逻辑。
- 为了适配手机而删除真实字段或改变业务口径。

### 5.3 允许保留的小型响应式行为

同一端内部的正常尺寸适配可以继续使用 CSS，例如：

- PC 在 1024 与 1440 宽度之间调整列宽。
- 手机在 390 与 440 宽度之间调整留白。
- 横竖屏重排。
- 文本自然换行和局部滚动。

这些属于同一套 UI 内部适配，不属于手机与 PC 混写。

## 6. 自动切换与状态保留

### 6.1 设备判断

- 唯一规则：`(max-width: 980px)` 为手机 UI，否则为 PC UI。
- 断点只允许在 `src/app/device.ts` 定义。
- 页面通过注入的 `AppDeviceMode` 使用当前端，不允许重复创建 `matchMedia` 监听。
- `980px` 和 `981px` 必须有专门回归测试。

### 6.2 路由

- 手机与 PC 使用同一组 URL。
- 路由记录只描述业务目的地，不直接绑定某一端的页面。
- 平台页面映射器根据 `AppDeviceMode` 动态导入对应页面。
- 自动切换后保持当前 path、query 和 hash。
- 不允许因为切换端自动跳回首页。

### 6.3 草稿状态

带表单或编辑行为的页面在拆分前，必须先把草稿状态从页面局部状态提升到共享 composable 或 Store：

- 按“路由 + 业务对象 ID”保存草稿。
- 手机 UI 和 PC UI 绑定同一份草稿。
- 切换端、旋转屏幕或重挂载页面时不丢失未保存输入。
- 保存成功或明确取消后清理草稿。
- 跨账号、跨日期草稿不得互相覆盖。

首批需要处理草稿契约的页面：

1. 录入页与库存录入。
2. 任务维护与任务结算。
3. 实际所得核算。
4. 行情维护和计划参数。

## 8. 每批次执行模板

每个批次固定执行以下步骤：

### A. 基线

- 记录当前 URL、可见功能、数据字段和主要操作。
- 补齐缺失的领域测试与现有行为 E2E。
- 保存 PC 与手机基准截图。

### B. 共享逻辑抽取

- 将查询、派生数据、校验和保存动作移入 composable 或 Store。
- 页面组件只负责呈现与调用动作。
- 为共享逻辑编写单元测试。

### C. 双端页面

- 新建 Mobile 页面，遵守 `docs/ui-development-rules.md`。
- 新建 Desktop 页面，使用适合键鼠、宽屏和信息密度的结构。
- 两端不得互相导入整页组件。
- 真正端无关的小组件可以进入 `shared-components`。

### D. 自动分流

- 在平台页面映射中注册双端 loader。
- 验证初次加载只请求当前端页面块。
- 验证 980/981 切换、URL 保持和草稿保持。

### E. 清理

- 删除旧页面中整页级媒体查询和无效模板。
- 合并重复样式和重复文案。
- 检查不再使用的文件、导入和选择器。

### F. 验收

- 单元测试。
- TypeScript 检查。
- 生产构建。
- 双端核心 E2E。
- 浏览器视觉复核。
- 控制台 warning/error 检查。

只有 A–F 全部完成，该页面才标记为“已拆分”。

## 9. 样式拆分计划

### 共享样式

继续全局加载：

- 颜色和语义 Token。
- 字体和基础 reset。
- 与平台无关的状态色、表单语义和无障碍基础。

### 手机专用样式

跟随 `MobileApp` 或 Mobile 页面动态加载：

- iOS 语义排版。
- 手机 Header、Tab Bar、搜索和 Sheet。
- VisualViewport、safe-area 和软键盘处理。
- 手机页面的触控反馈与移动端动效。

### PC 专用样式

跟随 `DesktopApp` 或 Desktop 页面动态加载：

- PC 顶部导航和工具区。
- 宽屏表格、工作台、分栏和密集筛选。
- hover、键盘焦点和批量操作状态。

最终目标是 PC 初始加载不再携带整套手机视觉 CSS，手机初始加载也不携带无用的 PC 页面样式。

## 11. 完成标准

整个项目只有同时满足以下条件才算完成：

1. 所有一级页面均有明确的 Mobile 与 Desktop 页面所有权。
2. 不再存在一个组件同时承载两套完整页面结构。
3. 所有业务计算、保存和同步逻辑只有一个来源。
4. 手机与 PC 的主要交互流程可以独立演进。
5. 自动切换保持路由、共享状态和未保存草稿。
6. 构建产物对手机和 PC 页面实现按需分块。
7. 全部单元测试、类型检查、生产构建和核心 E2E 通过。
8. 手机端通过 `docs/ui-development-rules.md` 的完整验收。
9. PC 主视口和小屏 PC 均无布局回退。
10. 仍然只有一套部署和一套数据。

## 12. 主要风险与处理

| 风险 | 处理方式 |
| --- | --- |
| 自动切换导致表单草稿丢失 | 先建立共享草稿 Store，再拆编辑页面 |
| 两端复制业务逻辑后结果不一致 | 业务逻辑只允许进入 domain、Store 或共享 composable |
| 全局 CSS 互相污染 | 平台样式动态加载，并逐页删除旧选择器 |
| 一次移动过多文件导致回归范围失控 | 每次只迁移一个完整业务切片 |
| 路由在两端表现漂移 | 共用路由语义，并增加路径契约测试 |
| 包体积因双 UI 增大 | 动态 import、构建块审计和首屏请求检查 |
| 中间阶段新旧结构并存 | 用迁移表记录所有权，完成一页立即清理一页 |
| 手机视觉改动破坏既有规范 | 每批次按手机端强制规则和指定视口重新验收 |

- 重构继续在当前发布分支上进行，不自动创建新分支或 PR。
